# Physical design tutorial: sources

The tutorial [physical-design.html](../physical-design.html) is built from the files here.
Everything it shows comes from one run of the flow, described under Provenance below.

| File | What it does |
|---|---|
| [page.html](page.html) | The page, without its data. |
| [build.py](build.py) | Inlines the data (`data.json`, gzipped) into the page and writes `../physical-design.html`. If there is no `data.json`, it keeps the data already in the page, so edits to the page need nothing else. |
| [regenerate.sh](regenerate.sh) | Remakes `data.json` from a run, then the page. It runs the four captures below in LibreLane's container, then `extract.py`. |
| [extract.py](extract.py) | Reads the run's DEFs, logs and reports, and the captures, and writes `data.json`. |
| [gpl/](gpl/) | Re-runs global placement stopped at intermediate states: initial placement after k iterations, Nesterov placement at overflow targets, and the routability snapshot. The end state is checked against the run. |
| [split/](split/) | Re-runs the repair, clock tree and hold steps, writing the layout just before and after the legalisation each ends with. The end state is checked against the run. |
| [guides/](guides/) | Dumps the route guides after antenna repair, which detailed routing follows. |
| [gds/](gds/) | Dumps the GDS: each cell master's shapes and the top cell's instances of them. |
| [provenance/](provenance/) | What the run was made from (below). |

## Provenance

The run is `runs/exp_rowtail`, made on 11 November 2026 by `tools/flow.sh harden rowtail`. The
inputs:

- **RTL:** the sources of commit
  [8e82a8f](https://github.com/zvea/tiny-breakout/tree/8e82a8f). `flow.sh` ran on a copy of
  them, which it deletes when it finishes.
- **Configuration:** `src/config.json`, `info.yaml` and `src/synth_excluded.cells` as at that
  commit (unchanged since), merged with `src/user_config.json`. That file is generated by
  `./tt/tt_tool.py --create-user-config` and not tracked, so a copy is kept here:
  [provenance/user_config.json](provenance/user_config.json). Its DEF template comes from
  Tiny Tapeout's [tt-support-tools](https://github.com/TinyTapeout/tt-support-tools) at
  `9d13ff3e3e6202090740110438c6a10c1d62ca0f`.
- **Tools:** LibreLane 3.0.14, in
  `ghcr.io/librelane/librelane@sha256:f91b21d75f79871f9ccf37451020b5d2f7b3236881a997ff709c561e8280a30f`.
  That image has Yosys 0.62 (`7326bb7d`) and OpenROAD 2026-02-17.
- **PDK:** sky130A from ciel, version `8afc8346a57fe1ab7934ba5a6056ea8b43078e71`.

Two netlists from the run are kept as the reference for any later work, such as a logic design
tutorial, that needs to match this one exactly:

- [provenance/synthesis.nl.v](provenance/synthesis.nl.v): the logical design, as synthesis wrote
  it.
- [provenance/final.pnl.v](provenance/final.pnl.v): the design after routing, with power pins.
  It also has every cell the flow added (buffers, the clock tree, delay cells, the antenna
  diode). The tutorial's cell names are these.

The run is reproducible. On 13 November 2026, `tools/flow.sh harden` on commit 8e82a8f's
`src/`, with the inputs above, gave the same synthesis netlist, final DEF and netlists byte for
byte, and the same GDS apart from its timestamps. To check synthesis again (about 4 minutes), in
a checkout of 8e82a8f with the `.venv` and `src/user_config.json` set up:

```sh
tools/flow.sh place check8e82a8f
cmp runs/exp_check8e82a8f/06-yosys-synthesis/tt_um_tiny_breakout.nl.v \
    <this folder>/provenance/synthesis.nl.v
```

Synthesis keeps a source location (file and line) only for the flip-flops, 208 of the 1,404
cells; ABC drops it from the logic gates. To map gates back to RTL, a logic tutorial would need
its own synthesis capture from 8e82a8f.
